**The self-test on the laptop** (stage times from the 24/11 baseline): toolchain 13 s, 534 unit tests 31 s, live
server + HTTP + performance 8 s, the Pi-era player in a browser 29 s (43 checks), **the site in a browser 6 min 48 s
(201 checks)**, the Atelier 38 s (26 checks) — 8 min 47 s in all, fully green. The site smoke is ~75 % of every
run, here and on GitHub.

**The site's first load.** `main.js` pulls 28 modules (368 KB before compression) through a chain 4 imports deep,
then the world adds ~15 more; 230 KB of CSS, of which `rooms.css` (66 KB) serves only the Archive's rooms. Every
file is served `max-age=0, must-revalidate` (right: a deploy is never half-old), so each visit asks again for every
file, in the order the imports discover them. The mini-player imports the whole telegraph line and the cast
(35 KB) for a name and a face; the visualiser imports the Canopy call map (27 KB) whatever mode is on.

**Repeated machinery.** 15 files run their own animation loop, 9 their own « pause when the tab is hidden »;
Paris time is computed 6 ways in the site (badge, sky, boat clock, Booth log, util, line).

## The plan, in order

### 1. GitHub's check: no apt, no wasted runs (S)
- Use the Google Chrome already on the runner (Chrome 157 on ubuntu-24.04) — no `playwright install --with-deps`.
  The laptop already runs the smoke on stable Chrome.
- ffmpeg as a pinned static build kept in the Actions cache (sha256 checked), not apt. *Or*, Ortis's call: commit the
  test station's synthetic fixture tones (~1 MB, generated, never music) and drop ffmpeg from the tests entirely —
  which also ends the laptop's ffmpeg-in-Temp problem.
- A docs-only push (only `docs/**`, root `*.md`) answers `test` green in seconds; the check keeps its name so
  Vercel's required check still sees it.
- The « What failed » grep stops quoting PASS lines that contain ✗ in their detail.

**Built 2026-11-24** on `claude/lighter-2026-11-24` (DECISIONS 2026-11-24): the runner's Chrome, the cached static
ffmpeg (b6.1.1, sha256-pinned, apt as fallback), `scripts/ci-scope.mjs` + `tests/ci-scope.test.js`. The docs-only rule
compares with the **last green commit**, not the previous push, so a cancelled code run is never skipped; a docs-only
push still runs the unit tests (~1 min). Not yet proven on GitHub: needs the branch pushed.

### 2. The site smoke, one file per room, run side by side (M)
TESTS-REVIEW §4: `radio`, `world`, `boat`, `echo`, `phone`, `print`, `tower` sharing one fixture tower and the
`check()` reporter. On GitHub each room is its own job (parallel), and a last job named `test` gathers them, so
Vercel's check is unchanged. On the laptop, `--only boat` runs one room; the full run takes 2–3 rooms at a time.
Target: GitHub ≈ 3 min wall clock, the laptop ≈ 5 min.

**Built 2026-11-24** on `claude/lighter-2026-11-24` (DECISIONS 2026-11-24): five parts cut by what each reads (the
parse tree says none reads another's values), `scripts/smoke/`; on GitHub `scope` → `self-test` (with `dist,tower`) and
`site` × `classic|world|phone` side by side → `test`, a verdict job. Laptop 203/203 (the two gathered axe checks are two
each now; the other 199 names unchanged). The laptop still runs the parts in a row: its Chrome is the bottleneck
(memory: other Chromes slow a run), so the « 2–3 at a time » half is not done. GitHub's time: not measured until pushed.

### 4. A faster first load, no bundler (S–M)
- The build (already a copy step) writes `<link rel="modulepreload">` for the start-up modules into every shell:
  one round trip instead of five. The source does not change.
- The mini-player's name-and-face, and the call map, out of the start-up chain (~60 KB, a sixth of it).
- `rooms.css` loaded by the rooms, as the boat already loads `boat.css`.
- Measured before and after in the browser (requests, bytes, time to the world's first frame), on a phone profile.

### 5. The good ideas, shared (M, behind a switch until Ortis says)
Two of the boat's additions he picked (F2 ① the sky keeps the station's time, ⑤ the bass moves the lake) are
boat-only code today. Made into two small services the whole site can use:
- `js/lib/station-time.js` — one Paris clock: minutes, the broadcast day (05:00), the part of the day
  (MATIN … NUIT), the sky's colours. The badge, the boat, the line's reset and the Booth's log read it.
- `js/lib/pulse.js` — one animation loop for the site: pauses when hidden, respects reduced motion, hands every
  subscriber `{ t, dt, bass, hit, sky }` and sets `--bass`, `--hit`, `--sky-*` on the page.

Then, as proposals he can look at (`?pulse=1`), within the mood board's « idle is calm »:
- Zone keeps the station's time like the lake: the glass and the visualiser's haze take the sky's tint
  (dawn, day, dusk, night) — the one slow ambient layer.
- The live indicators (LIVE dot, listening dot, the date badge's dot) breathe with the bass, as the ripples do.
- The selection shard's snap (MB-01) on the lists that still use a plain hover: the Booth's queue, the Crates,
  the Antenna's lanes, Playlists.
- « Click the thing, go to its place » (`data-go`) as one router rule instead of three handlers (boat, tags, cast).
- Echo: untouched unless he asks (« plain white until something better »); offered as a separate option — the
  paper warming in the evening.
