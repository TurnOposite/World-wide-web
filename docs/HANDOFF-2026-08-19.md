## What this run changed

Four things landed, all tested. Two things were deliberately **not** started.

### 1. The library is now curated, not just scanned

`server/lib/genre.js` and `server/lib/dedupe.js` are new.

- **Genre** is inferred from the *filename and folder*, not from ID3 tags —
  almost nothing in this library carries usable tags, because most of it came
  from YouTube rips. Fourteen buckets (`barber-beats`, `vaporwave`, `vgm`,
  `dnb-jungle`, `lofi`, `jazz`, `electronic`, `trip-hop`, `ambient`,
  `french-rap`, `chanson`, `classical`, `rock-pop`, `unsorted`). Rules are
  ordered data, first match wins; a mis-filed track is a one-line fix.
- **`foldText()`** normalises fullwidth (`ＶＥＲＩＤＩＳ`) and bold-math
  (`𝗟𝗢𝗦𝗧`) unicode. Without it roughly a third of the vaporwave in this
  library is unmatchable — which is exactly the third that needs matching.
- **Dedupe** is intrinsic to `scanLibrary()`, not a one-off cleanup script.
  The drive is meant to be swapped and refilled by hand, so a cleanup that ran
  once in August protects nothing in September. Two tracks are the same
  recording when their normalised titles match *and* durations agree within
  2s. Ties resolve by bitrate → lossless → size → unsuffixed name → path
  depth → path. That resolution is **total and deterministic** on purpose: if
  two scans disagreed, the library revision would flap and the schedule would
  re-era itself every 30 minutes.
- `publicTrack()` now carries `genreSlug` / `genreLabel`, so the API exposes
  them.

### 2. `scripts/ingest.mjs` — consolidate the six folders onto the USB drive

Separate from `npm run scan` on purpose: scanning is continuous and read-only,
ingesting is rare and destructive-ish. Conflating them would mean a routine
rescan could start copying gigabytes.

```bash
node scripts/ingest.mjs --dry-run                    # report only
node scripts/ingest.mjs --dest E:/RadioTowerMusic    # copy, foldered by genre
node scripts/ingest.mjs --dest /mnt/usb --move --flat
```

Writes `ingest-manifest.json` (every kept track, every dropped duplicate and
what it lost to). Sources come from `--source` flags, `ingest.sources.json`, or
the built-in defaults.

### 3. Reordering what's next — without breaking the station clock

This was the hard one. The station's whole claim is that the programme is a
pure function of wall time; letting someone reorder it is, naively, a direct
contradiction.

**The resolution: a reorder is a _permutation of a bounded window_.** Swapping
a 3-minute track for a 5-minute one would change `cycleSeconds`, which would
move every cycle boundary since the epoch — the exact catastrophe the era
mechanism exists to prevent. A permutation reorders the *same multiset of
durations*, so the window ends at precisely the same instant, everything after
it is bit-identical, and no era is created. Insert/delete/duplicate are
structurally impossible: the window's length is derived from `ids.length`.

- `Station.setQueueOrder({cycleIndex, startWithin, ids})`, `clearQueueOrder()`,
  `slotStartsAt()`, `queueOverride`.
- `GET /api/queue`, `POST /api/queue/reorder`, `POST /api/queue/clear`.
- **Auth:** `STATION_KEY` env var, constant-time compared. **Unset = endpoints
  disabled outright** (503), not open. This station is built to sit on a public
  Cloudflare tunnel; off-by-default is the only safe posture for a write
  endpoint on a public URL.
- **Safety fence:** `QUEUE_LOCK_SECONDS` (default 60) freezes the current
  track and anything starting within the next minute — Ortis's rule.
- Slots are addressed by `(cycleIndex, withinCycle)`, **not** by track id. A
  library smaller than the lookahead repeats ids across cycles, so "move track
  X" would name two different slots. This was a real bug caught by the tests.
- A library change drops the override rather than misapplying it.

### 4. A stale test repaired

`tests/api.test.js` parked the station by mutating `station.epoch`. Since the
era mechanism landed, `epoch` is only read in the constructor — the live time
origin is `era.startTimeMs`. The test had been silently failing. It now shifts
the actual anchor.
